## 缺陷清单（按严重度）

### P0-1 卡片接口不返回文档正文

- 复现：`GET /api/dsh-sourcelore-cards/repocard?repository_id=38923193`
- 实际：`files: ['claim-network.md', ...]` 只有**文件名数组**；
  `card` 对象里**没有** `documents` / `document_sections` 字段
- 预期：按用户第五节 §9 的统一视图契约，应含
  `document_id / document_sections / section_content / source_fact_refs / ...`
- 文件：`plugin/dsh-sourcelore-cards/index.js`（`/repocard` handler）
- 根因：handler 只对目录做 `readdirSync` 取 `.md` 文件名，**从未读文件内容**
- 影响：卡片只能显示「项目文档：5 篇」这种清单，永远读不到正文
- 修复：handler 读入 md 正文并按章节切分返回；前端渲染 Markdown

### P0-2 项目知识文档是空壳（200–1200 字节）

- 实测字节数：
  - is-number：overview 809 / structure 690 / deps 235 / claims 755 / evidence 539
  - preact：overview 829 / structure 1245 / deps 227 / claims 1206 / evidence 532
- 实际内容：只有标题 + 固定的「已知限制」样板文字
- 对比用户要求（§3.1 七类文档：项目总览/结构说明/模块依赖/代码知识/使用开发/主张证据/版本历史）
  —— **当前只实现了其中 2 类的骨架**
- 根因：`_md_*` 系列函数只做表格拼接，未整合 README 正文、Manifest 内容、源码符号
- 明确缺失：项目用途、技术栈、入口文件、主要功能、架构概述、安装/使用/构建说明

### P0-3 `code_rows` 从未被传入 → 模块关系永远为空

- 证据：全仓 grep `code_rows` 只有定义（`repo_graph_derivation.py:285`）
  和内部使用（`:295`），**没有任何调用方传值**
- 后果：`build_symbol_and_import_graph()` 收到空列表
  → `IMPORTS`/`DECLARES` 边全部为空
  → preact 的 `module-dependencies.md` 写成「无源码导入/声明观察」
- 但 `query --type code` 实际能拿到 13 条 re-export（`render -> ./render` 等）
- 严重度：高 —— 数据在库里，视图层没取

### P0-4 派生视图生成器不在源码里，是一次性脚本

- 全仓 grep `derive_repo_graph|write_derived_views` 无任何调用方
- 现有派生视图是 2026-11-10 我用手写临时 Python 脚本 `python3 - <<'PY'` 生成的
- 后果：**不可复现、无入口、无测试、无法增量更新**
- 修复：需新增正式 CLI 子命令（如 `sourcelore derive <rid>`）承载

### P0-5 树完整性：ROOT_ONLY 曾被标 COMPLETE

- 已知三个仓库树最大深度均为 0，只有根层条目（13/13/32）
- 快照 `completeness_status` 标 `COMPLETE`
- 严重度：高 —— 比标 PARTIAL 更危险，会让人以为数据完整
- 缓解：图谱派生已额外报 `tree_status: ROOT_ONLY` 并写入 limitations（仅视图层兜底，
  **采集层缺陷未修**）
